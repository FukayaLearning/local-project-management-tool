# 要件定義書

## 1. システム概要

### 1.1 背景・目的

- **背景**: オフライン環境で動作し、データベースサーバー等の複雑なインフラを必要としないプロジェクト管理ツールが求められている。また、バージョン管理システム(Git)を利用して変更履歴を確実に管理したいというニーズがある。
- **目的**: オフラインで完結し、JSON/CSVといった汎用フォーマットでデータを管理しつつ、Gitによる強力な履歴管理機能を持つプロジェクト管理ツールを提供する。これにより、ユーザーは場所を選ばず、安心してプロジェクト管理を行うことができる。

### 1.2 スコープ

- **対象範囲**:
  - 複数プロジェクトの作成・一覧表示・選択機能
  - プロジェクト単位の設定管理 (JSON)、グローバル基本設定の管理 (JSON)
  - タスクデータのCRUD操作機能 (CSV)
  - タスクデータの視覚的表示（リスト、ガントチャート）
  - プロジェクトごとの独立したGitリポジトリによる履歴管理機能 (Undo/Redo)
- **対象外**:
  - 複数ユーザーによる同時編集・リアルタイム同期（Gitによる非同期な共有は可能だが、本システムのスコープ外）
  - クラウドストレージとの直接連携
  - 既存データ構造からのマイグレーション機能

### 1.3 ユーザー定義

| ユーザー種別 | 説明                                                             |
| :----------- | :--------------------------------------------------------------- |
| ユーザー     | 本ツールを利用してプロジェクト管理を行う個人またはチームメンバー |

## 3. 非機能要求 (Non-Functional Requirements)

### 3.1 動作環境・制約 (ENV)

- **REQ-ENV-001**: インターネット接続がないオフライン環境でも全ての機能が動作すること。
- **REQ-ENV-002**: データの保存先はローカルファイルシステム（JSON/CSV）であること。
- **REQ-ENV-003**: 外部のデータベースサーバー（MySQL, PostgreSQL等）を必要としないこと。
- **REQ-ENV-004**: バージョンアップ（Dockerビルド交換）やツール再起動時でも、以前の変更履歴を引き継いで実行できること。

### 3.2 性能 (PERF)

- **REQ-PERF-001**: 一般的なPCスペックで、数千件程度のタスクデータを遅延なく操作・表示できること。

### 3.3 データ管理 (DATA)

- **REQ-DATA-001**: プロジェクトごとに独立したGitリポジトリを持ち、履歴を完全に分離すること。
- **REQ-DATA-002**: プロジェクトディレクトリ内の `setting.json` および `tasks.csv` をGit管理対象とすること。
- **REQ-DATA-003**: グローバル基本設定（`data/setting.json`）はGit管理対象外とすること。
