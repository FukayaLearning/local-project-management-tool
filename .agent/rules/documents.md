  各機能にユニークなID (Req-ID) を付与し、実装状況やテスト有無を追跡可能にします。

  ### 2.1 認証・ユーザー管理 (AUTH)

  | Req-ID | 機能分類 | 機能名 | 詳細・振る舞い | 優先度 | 備考 |
  | :--- | :--- | :--- | :--- | :--- |
  | **REQ-AUTH-001** | 認証 |ログイン | ユーザーIDとパスワードでログインできること。 | 高 | |
  | **REQ-AUTH-002** | 認証 | ログアウト | 任意のタイミングでログアウトできること。 | 高 | |
  | **REQ-AUTH-003** | 認証 | パスワード変更 | ログイン中のユーザーが自身のパスワードを変更できること。 | 中 | |

  ### 2.2 プロジェクト管理 (PROJ)

  | Req-ID | 機能分類 | 機能名 | 詳細・振る舞い | 優先度 | 備考 |

  ### 3.1 性能・パフォーマンス (PERF)
  *   **REQ-PERF-001**: ページロード時間は主要画面で2秒以内とすること（Wifi環境下）。
  *   **REQ-PERF-002**: 同時アクセス数 100ユーザーに耐えうること。
  ### 3.2 セキュリティ (SEC)
  *   **REQ-SEC-001**: 通信はすべてHTTPSで行うこと。
  *   **REQ-SEC-002**: パスワードはソルト付きハッシュ化して保存すること。
  *   **REQ-SEC-003**: APIはJWTによる認証トークンを必須とすること。
  ### 3.3 可用性・運用 (OPS)
  *   **REQ-OPS-001**: システム稼働率は 99.5% 以上を目標とする。
  *   **REQ-OPS-002**: 障害発生時はログをファイルに出力し、原因追跡可能であること。
