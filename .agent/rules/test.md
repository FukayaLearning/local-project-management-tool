# 試験ルール詳細

## 本書内表記

- (例:～)は、例示である。

  - (例:「workspace_root」は、本ワークスペースにおけるルートディレクトリを指す。)

## 単体試験ルール

### 単体試験スクリプト作成

単体試験スクリプトは次の通り作成すること。

- バックエンド／フロントエンドの単体試験実行する前に、それぞれの「単体試験仕様書ディレクトリ」/result/ ディレクトリを削除してから実行し、過去のエビデンスを破棄すること。
- バックエンド／フロントエンドの単体試験実行し、試験完了後に試験プロセスが残らないようにすること。
- バックエンド／フロントエンド単体試験実行時において、それぞれの「単体試験仕様書ディレクトリ」/result/ ディレクトリにエビデンス（試験実行時標準出力、カバレッジレポートなど）を格納すること。

### 単体試験コード作成

単体試験コードは次の通り作成すること。

- バックエンド／フロントエンドがそれぞれ単独で試験できる環境にすること。
- バックエンド／フロントエンドがそれぞれのプログラミング言語に合わせた単体試験フレームワークを利用する。
- Application層、Domain層を分岐網羅できるよう作成する。
- 異常系を除き、正常系の試験では本番運用時の動作を考慮した入力と出力期待値とすること。
- Infrastructure層はMockにする。
- フロントエンドは疑似レンダリングして画面テストすること。
- バックエンド・フロントエンドの単体試験コードがそれぞれの本番ビルド時に除外されるようにすること（除外されるための配置や設定を単体試験フレームワークの通例を参考にして行う）。
- 試験対象のソースコードにおいて、未サポート・未実装を示している場合は、試験対象外としてよい。

### 単体試験実行

単体試験は次の通り実行し、確認すること

- 単体試験実行スクリプトで試験実行すること。
- 試験実行後の「単体試験仕様書ディレクトリ」/result/ ディレクトリにエビデンス（試験実行時標準出力など）があること。
- 単体試験のエビデンスより試験実行件数とPASS件数を確認し、単体試験仕様書の試験件数と一致したら単体試験完了とする。

## 結合試験ルール

### 結合試験ディレクトリ構成

- 「workspace_root」/doc/test/integration/ # 結合試験仕様書／結合試験実行スクリプト格納ディレクトリ
- 「workspace_root」/doc/test/integration/scripts/ # 結合試験スクリプト格納ディレクトリ
- 「workspace_root」/doc/test/integration/result/ # 結合試験エビデンス（試験実行時標準出力など）

### 結合試験実行スクリプト作成

結合試験実行スクリプトは次の通り作成すること。

- 結合試験実行する前に「結合試験仕様書ディレクトリ」/result/を削除してから実行し、過去のエビデンスを破棄すること。
- 結合試験実行スクリプトの実行開始時は、必ずテスト用データベースの初期化やシードデータの投入（クリーンアップ）を行い、テストが毎回完全に同じ初期状態から実行されるように構築すること。
- 結合試験実行スクリプト引数より、デバッグ時はフロントエンド／バックエンドを開発者モードやデバッグモードで実行する。
- 結合試験実行スクリプト引数が特にない場合はフロントエンド／バックエンドを本番モードで実行すること。
- 結合試験実行し、試験完了後にフロントエンド／バックエンド／結合試験プロセスがすべて残らないようにすること。
- プロセスを終了させる前に、**バックエンドおよびフロントエンドの標準出力・標準エラー出力（サーバーログなど）もファイル（`backend.log`, `frontend.log`等）として 「結合試験仕様書ディレクトリ」/result/ ディレクトリに保存**すること。
- 試験実行のエビデンス（試験実行時標準出力など）を「結合試験仕様書ディレクトリ」/result/ ディレクトリに格納すること。
- テストがFAILした場合、E2Eテストフレームワーク（Playwright等）が生成するエラーのスタックトレースや詳細な結果を 「結合試験仕様書ディレクトリ」/result/ ディレクトリに確実に出力すること。

## 結合試験スクリプト（結合試験コード）作成

結合試験スクリプト（結合試験コード）は次の通り作成すること。

- 要件定義書の機能を網羅する。
- 画面操作のためE2Eテストフレームワークを利用すること。
- 画面操作フレームワークを活用し、テストがFAILした際はその時点の**スクリーンショットやUIのトレースデータ（Trace Viewer用等）を自動的にファイル出力**する設定を含めること。
- 結合試験の実行時引数で、ユーザ向けのデモ用に画面を表示しながら、画面操作の流れがユーザが見てわかる速度に切り替えられるようにすること。
- 結合試験において、「結合仕様書ディレクトリ」/result/ ディレクトリに結合試験がPASSしたことのエビデンス（試験実行時標準出力など）を格納すること。
- 結合試験のエビデンスは、**デバッグループ中はFAILのログも調査用に保持**し、デバッグが完了して最終的にPASSしたことを確認した後に不用なエラーエビデンスを削除する運用とすること。
- 結合試験スクリプト（結合試験コード）は、バックエンド・フロントエンドの本番ビルド時に混ざることがないようにすること。

### 結合試験実行

結合試験は次の通り実行し、確認すること

- 結合試験実行スクリプトで試験実行すること。
- 試験実行後の「結合仕様書ディレクトリ」/result/ ディレクトリにエビデンス（試験実行時標準出力など）があること。
- 結合試験のエビデンスよりFAILがある場合や、そもそも試験実施できていない場合は、デバッグとして結合試験実行スクリプトを実行する。
- デバッグが完了したら、最終確認として結合試験実行スクリプトでフロントエンド、バックエンドを本番モードで実行し、エビデンスより、結合試験仕様書の試験件数とPASS件数が同じことを確認し、結合試験完了とする。
